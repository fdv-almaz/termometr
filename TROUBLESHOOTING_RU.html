🌐 WiFi проблемы

Проблема: Дисплей показывает "No WiFi!"

Признаки: - На дисплее вместо температур видно "No WiFi!" - Serial Monitor показывает "Connecting to WiFi..." Решение: 1. Проверьте EEPROM конфигурацию: 
Загрузите конфиг-скетч и посмотрите Serial Monitor


Должно быть: "SSID: ваша_сеть"


Если пусто - переконфигурируйте EEPROM
2. Проверьте имя и пароль WiFi: 
На Linux - посмотрите доступные сети

nmcli dev wifi


Убедитесь, что:


- Имя сети (SSID) правильное


- Пароль введён без опечаток


- Сеть работает на 2.4 ГГц (не 5 ГГц!)
3. Проверьте сигнал WiFi: 
Serial Monitor должен показать RSSI (сигнал)


Оптимально: от -70 до -50 дБм


Если хуже -80 дБм - приблизьте маршрутизатор
4. Проверьте MAC фильтр маршрутизатора: 
На маршрутизаторе:


1. Найдите MAC адрес ESP32 (будет в Serial Monitor)


2. Добавьте его в список разрешённых устройств
5. Сбросьте настройки WiFi на ESP32: 
// Добавьте в setup() перед WiFi.begin():
WiFi.disconnect(true);  // Стереть сохранённые сети
delay(1000);

💾 Проблемы API

Проблема: "401 Forbidden" при отправке данных

Решение: 1. Проверьте API ключ в EEPROM: 
Serial Monitor датчика должен показать при загрузке:


"API Key: ваш_ключ"


Если пусто - переконфигурируйте EEPROM
2. Проверьте API ключ на сервере: 
Посмотрите переменную окружения

printenv | grep API_KEY


Или в Apache конфиге (если задали там)

grep -r "API_KEY" /etc/apache2/
3. Убедитесь, что ключи совпадают: 
EEPROM на датчике: "abc123..."


Переменная сервера API_KEY должна быть: "abc123..."
4. Проверьте, включена ли аутентификация: 
Проверьте ENABLE_AUTH в конфиге

grep ENABLE_AUTH /var/www/html/meteo/meteo/db.php


Если false, аутентификация отключена

Проблема: "Invalid input" при отправке данных

Решение: 1. Проверьте формат данных: 
Правильный формат:


/meteo/save.php?apikey=KEY&devid=1&temperatureUL=20.5&temperatureDOM=21.3&press=1013.25



Ошибки:


- temperatureUL=abc (не число)


- temperatureUL=999 (выше максимума 100°C)


- dev_id=0 (должно быть 1-255)
2. Проверьте диапазоны значений: 
Температура: -50 до +100°C
Давление: 300 до 1200 гПа
Device ID: 1 до 255
3. Посмотрите логи ошибок: 
tail -50 /var/www/html/meteo/logs/error.log

Проблема: "Database connection failed"

Решение: 1. Проверьте подключение к БД: 
Подключитесь вручную

mysql -u meteo_user -p meteo -h localhost

Если не работает - БД недоступна
2. Проверьте параметры БД в конфиге: 
grep "db_" /var/www/html/meteo/meteo/db.php


Убедитесь, что:


db_host = localhost (или IP сервера)


dbuser = meteouser


db_pass = правильный пароль


db_name = meteo
3. Проверьте, запущена ли MySQL: 
sudo systemctl status mysql

Если не работает:

sudo systemctl start mysql
4. Проверьте права доступа пользователя БД: 
mysql -u root -p

Выполните:

GRANT ALL PRIVILEGES ON meteo.* TO 'meteo_user'@'localhost';
FLUSH PRIVILEGES;

🖥️ Проблемы сервера

Проблема: Сервер не отвечает (timeout)

Решение: 1. Проверьте доступность сервера с ESP32: 
На ESP32 в Serial Monitor должно быть:


"HTTP Response: 200"


Если нет - сервер недоступен с сети ESP32
2. Проверьте IP адрес сервера: 
На сервере:

hostname -I


Этот IP должен быть в EEPROM ESP32


Проверьте: http://192.168.X.X/meteo/save.php
3. Проверьте firewall на сервере: 
Проверьте, открыт ли порт 80

sudo ufw status

Если закрыт:

sudo ufw allow 80/tcp
4. Проверьте Apache/Nginx: 
Для Apache:

sudo systemctl status apache2


Для Nginx:

sudo systemctl status nginx


Если не работает:

sudo systemctl restart apache2  # или nginx

Проблема: 404 Not Found

Решение: 1. Проверьте путь к файлам: 
ls -la /var/www/html/meteo/meteo/

Должны быть: save.php, getlast.php, db.php
2. Проверьте права доступа: 
Файлы должны быть читаемы www-data

sudo chown -R www-data:www-data /var/www/html/meteo
3. Проверьте URL в EEPROM: 
Serial Monitor должен показать:


"Calling URL: http://192.168.X.X/meteo/save.php"


Без опечаток и с правильной папкой meteo/

Проблема: 500 Internal Server Error

Решение: 1. Посмотрите логи ошибок Apache: 
sudo tail -100 /var/log/apache2/error.log
2. Посмотрите логи приложения: 
cat /var/www/html/meteo/logs/error.log
3. Проверьте синтаксис PHP: 
php -l /var/www/html/meteo/meteo/save.php

Должно быть: "No syntax errors"
4. Проверьте расширение php-mysql: 
php -m | grep mysql

Должно быть: "mysqli"


Если нет:

sudo apt-get install php-mysql

📊 Проблемы датчиков

Проблема: Температура всегда 85°C или -127°C

Причина: DS18B20 не подключен правильно или неисправен Решение: 1. Проверьте разводку DS18B20: 
GND (чёрный) → GND ESP32
VCC (красный) → 3.3V ESP32
DQ (жёлтый) → GPIO 15 + резистор 4.7kΩ к 3.3V
2. Проверьте резистор pull-up: 
Резистор 4.7kΩ ОБЯЗАТЕЛЕН между DQ и 3.3V


Без него датчик не работает
3. Проверьте адреса датчиков в коде: 
// Serial Monitor должен показать адреса датчиков
// getTempCByIndex(0) и getTempCByIndex(1) - индексы датчиков
4. Протестируйте датчик отдельно: 
// Загрузите пример из библиотеки DallasTemperature
// File → Examples → DallasTemperature
// Убедитесь, что датчик определяется

Проблема: Давление показывает 0

Причина: BMP280 не подключен или неправильный адрес I2C Решение: 1. Проверьте разводку BMP280: 
GND → GND ESP32
VCC → 3.3V ESP32
SCL → GPIO 21 (или I2C SCL)
SDA → GPIO 22 (или I2C SDA)
2. Проверьте адрес I2C: 
// В коде проверьте адрес:
bmp.begin(0x76);  // или 0x77
// Serial Monitor должен показать успешную инициализацию
3. Сканируйте I2C адреса: 
// Загрузите i2c_scanner из примеров
// Найдите адреса датчиков

💡 Проблемы памяти

Проблема: Устройство перезагружается или зависает

Решение: 1. Посмотрите свободную память: 
// Serial Monitor должен показать:
// "Free Heap: 200000"
// Если меньше 50000 - проблема памяти
2. Найдите утечку памяти: 
// Добавьте в loop():
Serial.printf("Free Heap: %d\n", ESP.getFreeHeap());
delay(1000);

// Если память уменьшается - утечка
3. Отключите ненужные библиотеки: 
// Удалите включение библиотек, которые не используются
// #include   → закомментируйте
4. Сбросьте EEPROM: 
EEPROM.begin(256);
EEPROM.write(0, 0);  // Сотрите всё
EEPROM.commit();
---

🔧 Дисплей e-ink проблемы

Проблема: Дисплей не обновляется или показывает мусор

Решение: 1. Проверьте разводку дисплея: 
MOSI → GPIO 23
MISO → GPIO 19
CLK → GPIO 18
CS → GPIO 5
DC → GPIO 17
BUSY → GPIO 4
RES → GPIO 16
2. Проверьте тип дисплея в коде: 
#include 
// Это для 2.13" чёрно-белого дисплея
// Проверьте, что это ваш дисплей
3. Протестируйте дисплей отдельно: 
// Загрузите пример из GxEPD
// Убедитесь, что дисплей реагирует

Проблема: "No server" на дисплее

Решение: 1. Проверьте URL в EEPROM: 
Serial Monitor дисплея должен показать:


"Sending to: http://192.168.X.X/meteo/getlast.php"
2. Проверьте доступность сервера: 
На машине с ESP32 сетью:

ping 192.168.X.X  # IP сервера
curl http://192.168.X.X/meteo/getlast.php
3. Увеличьте timeout подключения: 
// В коде дисплея измените:
const uint8t wificonnect_timeout = 60;  // Секунды

🔍 Отладка системы

Использование Serial Monitor

Откройте Serial Monitor в Arduino IDE


Скорость: 115200 baud



Ищите эти сообщения:


✓ "WiFi connected!" - успешное подключение


✓ "Data sent successfully" - данные отправлены


✓ "HTTP Response: 200" - успешный ответ сервера



✗ "Failed to connect" - ошибка WiFi


✗ "HTTP Error: 403" - ошибка API ключа


✗ "Database error" - ошибка БД

Проверка логов сервера

Логи ошибок приложения

cat /var/www/html/meteo/logs/error.log


Логи Apache

sudo tail -100 /var/log/apache2/error.log
sudo tail -100 /var/log/apache2/access.log


Логи MySQL

sudo tail -100 /var/log/mysql/error.log

Тестовые запросы

Проверить сохранение данных

curl "http://192.168.1.100/meteo/save.php?apikey=test&devid=1&temperatureUL=20&temperatureDOM=21"


Проверить получение данных

curl "http://192.168.1.100/meteo/getlast.php"


Проверить подключение к БД

mysql -u meteo_user -p meteo -e "SELECT COUNT(*) FROM data;"
